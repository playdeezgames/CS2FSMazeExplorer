## Original behaviour to preserve (reference)

Facts read from the F# source; the port must match unless a quirk below is decided otherwise.

- **Grid and maze:** 24 columns x 18 rows maze (`MazeColumns`, `MazeRows`) inside a 32x18 tile screen; the right 8 columns are the stats panel. The maze is a spanning tree grown Prim-style from a random cell (random frontier cell, joined to a random inside neighbour).
- **Start:** a random cell with more than one exit (not a dead end), random facing.
- **Items:** one per **dead end** (cells with exactly one exit). The list is the fixed items (LoveInterest 1, Amulet 1, Potion n, Exit 1, Hourglass n, Sword n; n by difficulty), truncated to the dead-end count, topped up with random Treasure 25 / Trap 20 / Shield 10 / Key 15 weights, then shuffled over the dead ends.
- **Monsters:** each item cell rolls its own weighted monster table (`ItemGeneration.itemMonsters`; Amulet always a Golem, LoveInterest always a Wizard, Exit never). A monster stands on the item cell.
- **Locks:** as many locks as there are keys, placed on random non-key item cells (a lock sits on the cell, not a door between cells). Entering a locked cell with no key is blocked; with a key, bump unlocks it (costs one key, no movement), the next bump moves in.
- **Combat:** bumping a monster fights one round, both sides at once: monster takes `max(0, playerAttack - monsterDefense)`, player takes `max(0, monsterAttack - playerDefense)`. Then a saving throw: if player defense > 0 and `rand(savingThrow) < monsterAttack`, defense drops by 1. A monster dies when damage >= health; kills are counted per type.
- **Death/potion:** when wounds + damage >= health, a potion (if any) is consumed and wounds reset to 0 (the fight sound is replaced by DrinkPotion); otherwise wounds = health (dead). Traps do the same potion rescue silently (no DrinkPotion sound) and count in `TrapsSprung`.
- **Pickups:** Treasure +1 loot; Trap +1 wound; Key +1 key; Sword +1 attack; Shield +1 defense; Potion +1; Hourglass +TimeBonus seconds to the deadline; LoveInterest **doubles Health** (does not clear wounds); Amulet sets a flag; Exit sets Stairs, ending the run (Exited).
- **Visibility:** `Visible` is a straight ray from the explorer in the facing direction until a wall. Turning or moving merges the old ray into `Visited`. Locked cells hide their contents until opened. The Amulet makes items on visited cells show; after game over everything is revealed.
- **Run state priority:** Dead, then Exited, then OutOfTime (deadline passed), else Alive. Commands are ignored unless Alive.
- **Pause/help/options:** the deadline is shifted by the paused duration on resume. Options: difficulty (Up/Down), `M` toggles sfx, `P` toggles whether pause is allowed. Difficulty applies on the next new game.
- **Score:** items: Loot 10, KeysAcquired 25, PotionsAcquired 50, SwordsAcquired 50, ShieldsAcquired 100, TrapsSprung -25, DoorsUnlocked 25, HourglassesAcquired 50, Amulet 500, Stairs 250; plus per-kill points (Skeleton 20, Zombie 40, Mummy 180, Ghoul 240, Golem 480, Wizard 600). Score screen shows both columns and a grand total.
- **Monster stats (health/attack/defense):** Skeleton 1/1/0, Zombie 2/1/0, Mummy 3/2/1, Ghoul 3/2/2, Golem 4/3/3, Wizard 5/3/3.
- **Constants:** initial attack 1, wounds 0, potions 3; health 10/7/5, time limit 600/480/360 s, time bonus 120/90/60 s, saving throw 6/4/3, hourglasses 6/5/4, swords 5/4/3, potions 6/5/4 (easy/normal/hard).

## Quirks found in the F# (port exactly; deal with afterwards)

Per D3, none of these are changed during the port. Each is reproduced as in the F#, and a test or comment should mark the spot so it is easy to find later. The "after the port" column is a suggestion only.

| # | Quirk | In the port | After the port |
| --- | --- | --- | --- |
| Q1 | `Drink` command exists in `Action.fs` but is a no-op, and no key maps to it; potions only auto-drink | Keep (no manual drink) | **Decided 2026-10-15: keep auto-drink, delete the dead command. Done: `Command_Kind.Drink` removed.** |
| Q2 | The play screen is repainted by a 1 s timer, so the clock only visibly ticks once a second and input repaints immediately | Core uses ms; display whole seconds as original | Likely fine as is |
| Q3 | `getTimeLeft` truncates toward zero and clamps at 0; OutOfTime when it hits 0 (so the last second is lost) | `int(seconds)` truncation | Likely fine as is |
| Q4 | **Measured in M1: 900 mazes (300 per difficulty), at least 137 dead ends each against 17 fixed items needed, so the Exit was never missing.** Item count is the number of dead ends, which varies per maze; if dead ends are fewer than the fixed list, fixed items are dropped from the end of the list order (Exit/Hourglass/Sword can be missing, Exit missing = unwinnable) | Reproduce; **measure how often the Exit is missing** and record it in the log | **User will deal with this after the port** (regenerate guard or place fixed items first) |
| Q5 | Locks can land on the Exit, Amulet or LoveInterest cells; lock count equals key count, keys are always reachable first (dead-end tree), so winnable by construction | Reproduce | Likely fine as is |
| Q6 | The start cell filter uses `Explorer.create` with a random sort over all matching cells; first match can be any non-dead-end | Random non-dead-end start | Likely fine as is |
| Q7 | Unpausing via Help/Options with `PauseAllowed=false` is blocked (returns to play instead) | Reproduce | Revisit with options UX |
| Q8 | `Amulet` name collides between `ItemType.Amulet`, `CounterType.Amulet` and `Sfx.Amulet` in F#; behaviour is as listed above | n/a | n/a |
| Q9 | Several screens do not clear on Esc paths; check Title/Help/Score screens' exact key handling when porting each | Read each `*Input.fs` per screen and copy exactly | Revisit if any screen traps the player |
| Q10 | Fights with a monster the player cannot hurt (attack <= defense, e.g. Golem defense 3 with attack 1) never kill it; the player can only bleed or avoid it | Reproduce | It is the point (Metaphor design); keep |
| Q11 | `FontTiles.fs` maps code point `\u0010` to `character6` (the spade) instead of `character16` (the right-pointing triangle); a copy-paste slip. The game never prints `\u0010` | Reproduce (`FONT_PATTERNS[16] == FONT_PATTERNS[6]`, covered by a test) | Fix if any text ever needs the glyph |
| Q12 | Trap is drawn with the Treasure pattern in Onyx, so it looks like loot in the dark colour; Key and Exit are also Onyx and are hard to see on the olive visible-cell fill | Reproduce | Possibly give traps their own look |
